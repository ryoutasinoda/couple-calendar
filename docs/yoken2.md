\# 不妊治療 記録・予定管理サービス 要件定義書



\## 1. 概要



\- \*\*目的\*\*: 不妊治療の通院・治療スケジュールと、生理周期・自己検査などの記録を、パートナーと共有しながら管理する

\- \*\*利用者\*\*: 本人 + パートナー(専用アカウントでログインし共有)

\- \*\*利用イメージ\*\*: スマートフォンでの簡単な記録がメイン

\- \*\*提供形態\*\*: Webサービス(PWA)

&#x20; - iOS/Androidどちらもブラウザからそのまま利用可能

&#x20; - プッシュ通知を使う場合は「ホーム画面に追加」してPWA化することを案内(iOS 16.4以降で対応)



\## 2. アカウント・共有



\- 本人・パートナーそれぞれが専用アカウントを作成してログイン

\- 同じ予定・記録を両アカウントで閲覧・編集可能

\- 予定ごとに「パートナーと共有」のオン/オフを設定可能



\## 3. 画面構成(モックアップで確認済み)



\### 3-1. カレンダー(ホーム画面)

\- 表示形式: \*\*月間カレンダー\*\*が基本

\- 配色: ベース色(白・ベージュなど)、カテゴリごとの色・アイコンは\*\*ユーザーが自由にカスタマイズ可能\*\*とする

\- 各日付セルに、その日の予定カテゴリを\*\*アイコンで表示\*\*(ドットのみでは種類が分かりにくいため採用)

&#x20; - カテゴリ: 診察 / 注射(通院) / 自己注射 / 服薬 / 移植 / 生理 / その他

&#x20; - カテゴリごとにアイコン + 淡い背景色で表示

\- 日付タップで、その日の予定一覧を下部に表示

\- 右下に予定追加ボタン(+)



\### 3-2. 生理期間の表示

\- 開始日を記録した時点で、\*\*開始日〜今日\*\*を「未終了(現在まで)」の期間として自動表示

&#x20; - 見た目は斜線パターン+破線枠で控えめに表現(過度に直接的な表現は避ける)

&#x20; - 開始日のマークは三日月アイコン(雫マークのような直接的な表現は避ける)

\- 終了日を記録すると、開始日〜終了日が確定期間として塗りつぶし表示に切り替わる



\### 3-3. 予定の新規登録

\- 種類をアイコン付きカードで選択(診察 / 注射(通院) / 自己注射 / 服薬 / 移植 / 生理 / その他)

\- 日付・時刻・場所(病院名)・メモを入力

\- 「前日に通知」「パートナーと共有」のオン/オフ

\- \*\*生理\*\*を選択した場合は、通常の日付・時刻フォームではなく

&#x20; - 未記録時:「開始を記録」ボタンのみのシンプルな画面

&#x20; - 開始記録済みの場合:「終了を記録」ボタンに切り替え



\### 3-4. 治療記録一覧(周期ごと)

\- 「周期」単位でカード表示(第1周期、第2周期…)

\- 各カードに以下を表示

&#x20; - 治療法(タイミング法 / 人工授精 / 体外受精 など)

&#x20; - 期間(開始日〜終了日、進行中は「〜」で終了日未定を表現)

&#x20; - ステータスバッジ(進行中 / 終了)

&#x20; - 通院・自己注射などの回数サマリー

&#x20; - 終了した周期は結果(\*\*陽性 / 陰性\*\*の2択、詳細な数値等は記録しない)を表示

\- カードタップでその周期内の予定・記録詳細に遷移



\### 3-5. 自己検査の記録

\- 種類: 排卵検査薬 / 妊娠検査薬(カテゴリは今後追加できる想定)

\- 結果: 陰性 / 陽性 / 判定中

\- 日時・メモを記録

\- \*\*1日に複数回の記録に対応\*\*(同じ日の記録は一覧で下に並べて表示)



\### 3-6. 費用記録

\- 通院・治療にかかった\*\*金額の簡単な記録\*\*に対応する

\- 家計簿アプリとの連携は行わず、本サービス内で完結するシンプルな記録機能とする

\- 予定・記録に金額欄を任意で入力できる程度の位置づけ(詳細な費用管理・集計機能は範囲外)



\## 4. 周期(サイクル)の区切り方



\- \*\*基本は自動区切り\*\*: 生理開始日を基準に、次の生理開始日の前日までを1周期とする

\- 自動区切りにした場合の懸念点と対応方針

&#x20; | 懸念点 | 対応方針 |

&#x20; |---|---|

&#x20; | 生理が来ない周期(妊娠判定待ちなど)がいつまでも終了しない | 一定期間経過、または妊娠判定の記録をもって自動終了とする補助ルールを設ける |

&#x20; | 生理不順で開始日の記録が数日ずれる/記録を忘れる | 開始日を後から編集できるようにする |

&#x20; | 治療を一時中断した期間も1周期として数えてしまう | 手動で周期の境界を分割・統合できる補正機能を用意する |

\- 上記の通り、\*\*自動区切り + 手動での境界編集\*\*をハイブリッドで採用する



\## 5. 通知



\- Web Push通知に対応(iOSはホーム画面追加が必要)

\- 予定ごとに前日・当日などの通知有無を選べる

\## 7. 技術方針



\- シンプルな構成で、運用コストを抑えることを優先する

\- 開発者自身でコードを書いて実装する(ノーコード/ローコードは使わない)

\- 利用人数は本人+パートナーの2人を前提とし、大規模なアクセスは想定しない



\*\*構成案(たたき台)\*\*

\- フロントエンド: Next.js(PWA対応、モバイル表示中心)

\- バックエンド/DB/認証: Supabase(PostgreSQL + 認証 + リアルタイム同期をまとめて利用でき、2人規模なら無料枠内で運用可能)

\- ホスティング: Vercel(Next.jsとの相性がよく、個人利用規模なら無料枠で足りる想定)

\- プッシュ通知: Web Push API(PWAとして「ホーム画面に追加」した状態で送信)



このスタックは一例なので、実装を始める段階で改めて詳細を詰める想定とする。



\## 8. データベース設計(たたき台)

| created\_at | timestamp | |



\*\*users(ユーザー)\*\*



| カラム | 型 | 備考 |

|---|---|---|

| id | uuid | PK(Supabase Authと連携) |

| household\_id | uuid | FK → households |

| display\_name | text | |

| role | text | 'self' / 'partner' |



\*\*categories(予定カテゴリ)\*\* — カスタマイズ対応



| カラム | 型 | 備考 |

|---|---|---|

| id | uuid | PK |

| household\_id | uuid | FK → households |

| name | text | 診察/注射(通院)/自己注射/服薬/移植/生理/その他 など |

| icon | text | アイコン識別子 |

| color | text | カテゴリ色 |

| is\_default | boolean | 初期プリセットかどうか |



\*\*schedules(予定)\*\*



| カラム | 型 | 備考 |

|---|---|---|

| id | uuid | PK |

| household\_id | uuid | FK |

| category\_id | uuid | FK → categories |

| cycle\_id | uuid | FK → cycles(nullable) |

| date | date | |

| time | time | nullable(生理は時刻なしもあり) |

| location | text | 病院名など |

| memo | text | |

| amount | integer | 費用記録(nullable) |

| notify\_before\_day | boolean | 前日通知 |

| shared | boolean | パートナー共有 |

\*\*period\_records(生理期間)\*\*

|---|---|---|

\*\*self\_tests(自己検査)\*\*



| カラム | 型 | 備考 |

|---|---|---|

| id | uuid | PK |

| household\_id | uuid | FK |

| cycle\_id | uuid | FK(nullable) |

| type | text | '排卵検査薬' / '妊娠検査薬' |

| result | text | '陰性' / '陽性' / '判定中' |

| tested\_at | timestamp | 日時(1日複数回対応) |

| memo | text | |



\*\*設計メモ\*\*

\- cycles は period\_records の開始日をトリガーに自動生成し、次の開始日が来たら前の周期の end\_date を自動セットする(自動区切り+手動補正の要件に対応)

\- schedules.amount で「簡単な金額記録」をカバーし、専用の費用テーブルは設けない

\- categories はhousehold単位で自由に色・アイコンを変更・追加できる設計
